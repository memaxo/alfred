## Purpose / Big Picture

Mindscape is already integrated and “real” in `apps/web` (ReactFlow canvas, persisted store, graph edge persistence, and workflow stream → UI receipts). v2 is a **simplification + hardening** pass that preserves existing behavior while making the architecture easier to change safely.

Goals:

1. **Preserve and codify current invariants** with tests as the contract (edge persist/rollback, workflow receipts, graph hydration).
2. **Standardize node UX using existing primitives** (`MindscapeNode`, `useLOD`, `useNodeFocus`, shared LOD components) and reduce per-node divergence.
3. **Make WebGPU paths explicitly gated per build target**: use Vite/TanStack Start-compatible gating in `apps/web` (via `import.meta.env` + conditional dynamic imports), and only use Bun `bun:bundle` feature flags in Bun-built packages (not in the Vite web app).
4. **Refactor the Mindscape store safely** (persistence-compatible modularization / migrations) without breaking localStorage or tests.

Non-goals (must be separate plan/approval):

- Turning Mindscape into an n8n-style typed DAG execution engine (this plan will not invent a new `packages/mindscape` runner).
- Destructive deletions/moves of nodes/engines without explicit approval in this session.

Success is demonstrated by:

- `apps/web/src/components/__tests__/mindscape.edge-persistence.test.tsx` passing (persist + rollback).
- `apps/web/src/components/__tests__/mindscape.monitor.test.tsx` passing (workflow stream → context cache receipts).
- `apps/web/src/components/__tests__/mindscape.graph.test.tsx` passing (graph query hydrates nodes).
- A build verification that is **realistic for Vite**: when the WebGPU flag is off, the relevant web bundle(s) contain **no WGSL strings** and do not initialize WebGPU (e.g. no `GPUDevice`/`navigator.gpu` usage in the gated path).

## Surprises & Discoveries

### Phase 4 (2025-12-21)

1. **Missing type exports from Phase 3**: The store modularization in Phase 3 inadvertently removed type exports (`ArtifactData`, `KnowledgeNodeData`, etc.). These were restored to `mindscape.schemas.ts` to break circular dependencies.

2. **React Flow type variance**: React Flow's `Node<T>` type has `type?: string` (optional), causing type incompatibilities when using generic types like `OnNodesChange<ArtifactNode>`. Solved by using base types without generics for handlers and adding type assertions where needed.

3. **Circular imports in store slices**: The new store slices (`graph.ts`, `persist.ts`, `types.ts`) were importing from `../mindscape` which re-exported from them, creating a cycle. Fixed by importing directly from `../mindscape.schemas`.

## Decision Log

### Phase 4 Decisions (2025-12-21)

1. **Graph helpers location**: Created `lib/mindscape/graph.ts` for pure graph transformation helpers (node ID extraction, edge mapping, knowledge node creation). This reduces coupling between `canvas.tsx` and `initializer.tsx`.

2. **URL helpers extraction**: Moved `clearSearchParams` to `lib/mindscape/url.ts` since it's a pure DOM utility.

3. **Type exports location**: Added missing type exports (`ArtifactData`, `KnowledgeNodeData`, etc.) to `mindscape.schemas.ts` rather than the store entry point. This breaks circular dependencies between store slices.

4. **ArtifactNode type simplification**: Changed `ArtifactNode` from `Node<ArtifactData, ArtifactType | string>` to `Node<ArtifactData>` to avoid type variance issues with React Flow's generic handlers. Runtime type safety is maintained via Zod schema validation.

5. **LOD hooks re-export**: `components/mindscape/lod.ts` now re-exports from `lib/mindscape/lod.ts` instead of being a placeholder, enabling simpler imports from components.

## Context and Orientation

### Current State Problems

Mindscape is not a disconnected prototype; it is already integrated across several surfaces:

- **ReactFlow Mindscape (`/mindscape`)**: `apps/web/src/components/mindscape/canvas.tsx` renders ReactFlow nodes/edges backed by `useMindscapeStore`. Edge creation persists to the graph via `trpc.graph.connect` with rollback on failure (covered by `mindscape.edge-persistence.test.tsx`).
- **Workflow stream monitor**: `apps/web/src/components/mindscape/monitor.tsx` records `context` + `data-cache-handoff` receipts into `useMindscapeStore.contextCache` and clears on completion/error (covered by `mindscape.monitor.test.tsx`).
- **Graph hydration**: `canvas.tsx` hydrates knowledge nodes from `trpc.graph.runQuery` results (covered by `mindscape.graph.test.tsx`).
- **WebGPU is present and referenced**:
  - `apps/web/src/lib/mindscape/gpu/{engine,renderer}.ts` (imports `*.wgsl?raw`) is used by `apps/web/src/routes/index.tsx` (landing page) and has `apps/web/src/lib/mindscape/gpu/engine.test.ts`.
  - `apps/web/src/hooks/use-cortex-engine.ts` uses `@alfred/cortex` and is mounted by `apps/web/src/routes/_protected/settings/visual.tsx`.

Remaining problems to solve in v2:

**Problem 1: WebGPU bundling/gating is not aligned with the web build**
- The plan previously proposed Bun `bun:bundle` feature flags inside `apps/web`. That is risky/incompatible: `apps/web` is Vite/TanStack Start.
- WGSL is imported via `?raw` (`apps/web/src/lib/mindscape/gpu/renderer.ts`), so any static import of the renderer will ship shader strings; we need Vite-friendly gating to exclude that code when disabled.

**Problem 2: Node UX is mostly standardized, but still drifts**
- A shared shell already exists: `apps/web/src/components/mindscape/nodes/mindscape-node.tsx` (`MindscapeNode`) + `apps/web/src/components/mindscape/lod.ts` + `nodes/shared-lod.tsx`.
- The remaining work is an audit + consolidation pass: ensure every node uses the shared shell/LOD patterns consistently and eliminate duplicated micro-patterns.

**Problem 3: Store is large and persistence-coupled**
- `apps/web/src/store/mindscape.ts` is ~600 lines and persisted (`name: "mindscape-storage-v2"`). It mixes graph state, cache state, receipts, feedback, and persistence helpers.
- Splitting stores must account for persistence compatibility and test stability; prefer modularization and explicit migrations.

**Problem 4: “Execution” already exists (graph + workflow), but semantics are spread out**
- Edges are not purely visual; they have persistence semantics.
- Workflow/context events already drive UI receipts.
- The opportunity is to tighten boundaries and reduce coupling across `canvas.tsx`, `monitor.tsx`, and `useMindscapeStore`.

### Terms Defined

- **Artifact node**: A ReactFlow node backed by `ArtifactData` in `useMindscapeStore`.
- **Graph-backed node**: A node whose `data.graph` carries identifiers (`dbId`, `hgHash`, `resource`) used for persistence/traversal.
- **Receipt**: A `SearchReceipt` emitted by workflows as `context` / `data-cache-handoff`, stored in `useMindscapeStore.contextCache`.
- **LOD (Level of Detail)**: Zoom-dependent render modes (`tiny`/`small`/`medium`/`full`) via `useLOD()`.
- **Focus**: The single focused node id (`focusedNodeId`) that dims all others via `useNodeFocus()`.
- **WebGPU gating**: Vite env + conditional dynamic import to exclude WGSL/WebGPU init when disabled.

## Risks

- **Bundler/feature-flag mismatch**: Bun `bun:bundle` flags do not apply to the Vite web app; gating must be done with `import.meta.env` + tree-shakeable patterns.
- **WebGPU portability**: WebGPU is not universally available; all WebGPU paths must degrade to Canvas2D/WebGL/no-op without crashing.
- **WGSL bundling**: `?raw` shader imports will ship if the module is imported; isolation is required.
- **Store persistence**: `mindscape-storage-v2` must remain compatible or ship explicit migrations; store splits risk data loss.
- **Refactor blast radius**: `canvas.tsx`, `monitor.tsx`, and `store/mindscape.ts` are coupled; keep existing Mindscape test suites as the contract.
- **React Flow controlled flow contract**: Store modularization (Phase 3) must preserve `onNodesChange`/`onEdgesChange`/`onConnect` handler signatures; breaking these breaks ReactFlow integration.
- **Node data immutability**: All node updates must remain immutable (spread operators); mutating node data causes React Flow render bugs.
- **SSR hydration**: Routes with `ssr: false` cannot access browser APIs during SSR; any new Mindscape routes must set this flag.

### Phase 1: WebGPU gating (Vite-first)

3. Decide the scope of “WebGPU-free build”:
   - Minimal: only guarantee the landing `MindscapeEngine` shaders are excluded when disabled.
   - Strict: also gate Cortex preview (`useCortexEngine` / settings visual route) so the entire app build can be WebGPU-free.
4. Add a build verification that matches Vite reality:
   - Extend `scripts/verify-build.ts` or add a dedicated script (e.g. `scripts/verify-mindscape-webgpu.ts`) to build `apps/web` with the flag off and assert `dist/` does not contain shader strings (`compute.wgsl`, `fragment.wgsl`) or WebGPU init tokens (`GPUDevice`, `navigator.gpu`).

## Migration, Idempotence, and Recovery

- **Persistence first**: any change to persisted Mindscape state must be backward compatible or provide explicit `persist` migration; never silently drop user layouts.
- **Feature gating**: WebGPU must degrade gracefully at runtime (non-WebGPU browsers) and be excludable at build time (Vite flag + verifier).
- **No destructive cleanup**: node/engine removals require explicit approval.
- **Failure modes**: graph/workflow network failures must rollback local UI state (already covered by tests); keep these tests as non-negotiable.
